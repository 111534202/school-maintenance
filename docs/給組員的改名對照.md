這份文件給林政寬、王佑恩、劉家芸。專案的資料表與欄位名稱做了一次統一整理，**你們各自分支裡用到舊名稱的程式、畫面、種子資料、測試都要跟著改**，不然合併後會出錯。
改名的完整邏輯與每個欄位的最終名稱，見 `docs/資料庫命名規範與資料字典.md`（第 9 節是定案紀錄）。

## 一、先看這個：怎麼合併

1. 先把自己分支上的東西 commit 好。
2. 在自己的分支執行：

```bash
git fetch origin
git merge origin/integrate/all
```

3. 有衝突時，**一律以這份文件的新名稱為準**，不要用舊名稱。
4. 合併完成後，在自己的電腦執行：

```bash
php artisan migrate        # 只改名稱、補外鍵，資料會轉換、不會遺失；執行前建議先備份自己的資料庫
php artisan test           # 全部測試要通過
```

5. 如果你自己的分支有新的 migration、Model 或畫面，請照第四節的規則取名，並執行 `php artisan docs:schema` 更新文件。

> `php artisan migrate:fresh --seed` 會清空資料庫，只在你不在意本機資料時使用。

## 三、每個人要檢查的地方

### 林政寬（教室、設備、用戶、身分、部門主檔）

- `classrooms`：`room_code`、`room_name`、`room_type` → 控制器的搜尋與驗證、`ClassroomSeeder`、表單 `_form.blade.php`、列表、設備頁顯示教室的地方（`$device->classroom->room_name` → `->name`）。
- `devices`：`warranty_until` → `warranty_end_date`（控制器驗證、表單、顯示頁、`DeviceSeeder`）。
- `users`：`username` → `account`（登入、用戶表單、用戶列表、`UserSeeder`、`UserDemoSeeder`、用到 `username` 的測試）。
- `roles`：`slug` → `role_code`（`RoleSeeder`、`RoleController`、`CheckRole`、`User::isAdmin()` 與判斷是否管理員的地方）。
- `departments`：`code` → `department_code`（`DepartmentController`、表單、列表、`DepartmentSeeder`）。
- 你們整合分支裡用到的「建立身分並直接傳 `permissions` 陣列」寫法**不用改**。

### 王佑恩（保養、AI、設備履歷）

- 保養項目、計畫的表單：原本是文字輸入框（`category`、`device_category`），**改成設備類別下拉選單**，欄位名稱是 `device_category_id`（Request 驗證是 `exists:device_categories,id`）。
- 保養計畫、保養工單：**指定了設備（`device_id`）之後不再另存類別**，儲存時會自動清掉 `device_category_id`；要顯示類別名稱請用 `$order->categoryName()`／`$plan->categoryName()`（有設備用設備的類別，沒有設備才用自己的類別）。
- `PreventiveCandidateService`、`DueMaintenanceOrderGenerator` 建立工單時，不用再傳設備類別名稱。
- 保養結果：
  - 表單不再送 `executed_by`，由控制器用登入帳號寫入；顯示執行人用 `$result->executor?->name`。
  - `notes` → `note`（Request、Model、表單、`NgToRepairService`、`AiDemoDataSeeder`、測試）。
- 設備履歷、保養工單畫面裡用到 `$order->device_category`、`$item->category`、`->result->executed_by` 的地方都要改。
- `MaintenanceResultFactory`：`executed_by` 預設 `null`，需要執行人的測試自己帶入使用者編號。

### 劉家芸（零件庫存、預約、維修扣庫存）

- 資料表 `repair_part_usage` → `repair_part_usages`：`RepairPartUsage` Model 的 `$table`、測試裡 `assertDatabaseHas('repair_part_usage', …)`／`assertDatabaseCount(…)` 的資料表名稱。
- 預約：`classroom_reservations.user_id` → `requester_id`；`ClassroomReservation::user()` → `requester()`；控制器 `with(['classroom','user'])` 要改成 `['classroom','requester']`；畫面 `$reservation->user?->name` → `$reservation->requester?->name`；測試建立預約時的欄位。
  - **注意**：操作日誌（`audit_logs.user_id`）的欄位名稱**沒有改**，測試裡檢查日誌的地方仍然是 `user_id`。
- 預約畫面顯示教室：`$classroom->room_name`／`room_code` → `name`／`classroom_code`。
- 零件庫存的路由已改用權限 `parts.manage`（原本是 `role:admin,it_manager`），選單也加了「零件庫存」連結；自訂身分勾這個權限就能進。

## 四、之後新增資料表或欄位要遵守的規則（摘要）

完整規則在 `docs/資料庫命名規範與資料字典.md` 第 1 節，這裡只放最常用的：

| 要取名的東西 | 規則 | 例子 |
|---|---|---|
| 資料表 | 小寫英文、底線、複數：`［領域詞］＿實體詞` | `devices`、`repair_logs` |
| 主鍵 | 一律 `id` | |
| 指向其他資料表 | `<資料表單數>_id`，一定要有外鍵 | `device_category_id` |
| 指向人 | 只能用 `requester_id`／`manager_id`／`assigned_to`／`*_by` | `reviewed_by` |
| 是／否 | `is_`、`has_` 開頭 | `is_active` |
| 日期時間／日期／時刻 | `_at`／`_date`／`_time` | `reviewed_at` |
| 狀態 | `status` | |
| 稱呼／代碼／備註 | `name`／`<實體>_code`／`note`（單數） | `device_code` |

做完後執行這兩個指令，不合規則或文件過期，測試會直接告訴你：

```bash

php artisan docs:schema          # 資料表或欄位改了以後，重新產生文件
```

## 五、全域搜尋時的注意事項

用「搜尋取代」改名時，下面這幾個字會誤傷，請不要整個專案一次取代：

| 要小心的字 | 為什麼 | 做法 |
|---|---|---|
| `slug` | `Str::slug(...)`（`config/` 裡）是 Laravel 內建函式；程式裡的變數 `$slug` 不是欄位 | 只改 `'slug'`（欄位名稱的字串）和 `->slug` |
| `username` | `config/database.php`、`config/mail.php` 的 `env('DB_USERNAME')` 是環境設定 | 不要動 `config/`、`.env`；程式裡只改欄位用法 |
| `name`（`room_name` 改成的新名稱） | `name` 是很多欄位共用的字 | 只改 `room_name`，不要反過來全域搜尋 `name` |
| `database/migrations/` 裡**舊的** migration | 它們描述「當時」的資料表結構，不能改 | 不要改舊 migration；新的改名請寫新的 migration |
| `login`／`logout` | 路由名稱 `route('login')`、表單欄位 `login` 也叫這個名字 | 只改傳給 `AuditLogger::log()` 的第一個參數，以及語言檔 `audit.php` 的 `actions` 區塊 |
