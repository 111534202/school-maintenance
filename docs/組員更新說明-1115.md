# 組員更新說明（11/15 這一批）

這份說明給林政寬、王佑恩、劉家芸。先看「你要做的事」，其他是新功能怎麼用。

## 一、你要做的事（拉新版後，3 步）

在專案資料夾打開終端機：

```bash
git pull origin integrate/all
composer install
php artisan migrate
```

- `composer install`：這次新增了「靜態分析」和更新了幾個套件的安全修補，不跑會缺套件。
- `php artisan migrate`：新增了一張「批次匯入紀錄」表。
- 跑完後建議執行一次 `php artisan test`，應該全部通過。

## 二、新功能（網頁上看得到的）

| 在哪裡 | 新增什麼 |
|---|---|
| 設備主檔、用戶主檔 | 右上角「批次匯入」：下載範本，用 Excel 填好上傳 |
| 批次匯入頁 | 下面有「最近的匯入紀錄」，匯錯可以按「整批復原」 |
| 設備主檔 | 「列印 QR 貼紙」：一次印出目前篩選的設備貼紙（A4，一次最多 240 張） |
| 設備主檔、用戶主檔、操作紀錄 | 「匯出 Excel」：依目前的篩選條件輸出 |
| 系統管理 → 寄信設定 | 填寄信用的信箱，不用改程式；填完要先「寄測試信」再啟用 |

批次匯入的流程：下載範本 → 填寫 → 上傳預覽（會標出哪一列錯在哪）→ 確認才寫入。有錯的列會自動略過，不會影響正確的列。

整批復原的規則：設備會改成「停用」、用戶會被刪除（都可以還原，資料不會消失）；已經有報修、保養、預約紀錄或已登入過的，會保留不動。

## 三、新的自動檢查（GitHub 會自己跑）

每次 push，GitHub 會自動跑四組檢查，在 GitHub 的 Actions 頁籤看結果：

1. 完整自動測試
2. 用真正的 MySQL 從零建資料庫，並檢查資料字典有沒有更新
3. 套件安全弱點檢查、靜態分析、新增檔案的程式風格
4. 用真的 Chrome 操作網站的流程測試

**紅燈不要慌**：點進去看哪一步失敗、錯誤訊息是什麼，通常一兩行就能看出原因。

## 四、之後寫程式要注意的 4 件事

1. **改資料表要改資料字典**：新增或修改資料表後，執行 `php artisan docs:schema` 更新文件，再一起 commit，不然 CI 會紅燈。新的資料表還要到 `app/Console/Commands/GenerateSchemaDocs.php` 補中文名稱。
2. **新增的 PHP 檔要排好格式**：commit 前執行 `composer format`，它會自動整理。**舊檔案不強制**，你不用特地去改別人的檔案。
3. **靜態分析不能增加新問題**：`composer analyse`。舊的問題記在 `phpstan-baseline.neon`，你新寫的程式不要再增加。
4. **模型的欄位說明要放在最上面**：模型檔的說明註解（`@property` 那一段）要放在 `#[Fillable(...)]` 這類標記的**上方**，放在下方分析工具讀不到。

## 五、想自己跑完整檢查

```bash
php artisan test            # 完整自動測試
composer analyse            # 靜態分析
composer format:check       # 程式風格檢查（不改檔案）
python tests/e2e/run.py     # 瀏覽器流程測試（需要先看 tests/e2e/README.md 的第一次設定，比較慢）
```

## 六、有問題找誰

整合與這批的功能：彭仕衡。各模組的程式維持原本的負責人，這批沒有改動你們的業務邏輯，只有補型別說明和少數小修正。

## 11/17 追加更新

拉新版後要多跑一次 `php artisan migrate`（新增兩個欄位：保養工單的「開始時間」、報修單的「驗收人」）。

| 新增或改動 | 說明 |
|---|---|
| 保養「待轉報修」直接建報修單 | 點「待轉報修」或「建立報修單」會開報修表單，設備與故障描述都先填好 |
| 保養工單「開始保養」 | 負責人按了才變「進行中」，並記下開始時間 |
| 保養排日期可以看課表 | 修改排定日期、AI 核准時，都能按鈕看設備所在教室的一週課表 |
| 報修附件 | 手機大照片自動縮小再上傳；報修單直接顯示縮圖；檔案欄位改用檔案類型，手機會直接開相簿 |
| 我的報修 | 所有身分的選單都有，只列自己提出的 |
| 空間申請匯出 | 先預覽，可勾選欄位與申請 |
| AI 預防保養工單 | 編號 `AI-00012`（定期保養是 `MO-`）；核准時要選排定保養日期 |
| 驗收指派專人 | 派工時可指定驗收人；除了管理員，只有報修人、維修人員、驗收人看得到「待驗收」「已結案」的案件 |
| 零件單價與成本分析 | 只有有「零件庫存」權限的人看得到單價、小計、材料費總額，成本分析報表（含兩種匯出）也一樣；維修人員、主管不再能進成本分析 |

要注意的幾件事：
1. 看「待驗收／已結案」案件的範圍收緊了：能派工的主管、設備管理員，也只看得到與自己有關的。統計與成本報表不受影響。
2. 沒有報修人的案件（例如保養 NG 轉來的）：派工時請指定驗收人，否則只有系統管理員能驗收。
3. 新增的 `tests/Feature/PermissionMatrixTest.php` 會逐一檢查「每個身分 × 每個頁面」的權限，新增頁面時它會自動檢查，不用改；只有網址帶參數的頁面，需要在它的 `fixtures()` 補一筆示範資料。
