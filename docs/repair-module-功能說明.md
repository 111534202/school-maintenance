# feature/repair 模組功能說明（供簡報／成果書使用）

負責人：彭仕衡（111534205）｜分支：`feature/repair`｜依《第五週個人工作計畫》第 6 項整理。

## 模組定位

負責「自助除錯、報修、派工、維修與驗收」整條主流程，是使用者從發現設備故障
到問題真正解決的完整路徑。

## 操作步驟（使用者視角）

1. **自助排除**：使用者在「自助知識庫」查詢常見問題，照步驟排除。
2. **判斷結果**：
   - 解決了 → 按「問題已解決」，結束。
   - 沒解決 → 按「無法排除，前往報修」，自動帶入標題與描述提示，跳到報修表單。
3. **送出報修**：填寫故障描述、影響程度（輕微/中等/嚴重）、是否影響上課、設備位置，
   可附故障照片或短片。
4. **主管派工**：主管在「維修案件看板」看到新案件，指定維修人員與預計處理日期；
   派工後仍可「重新指派」換人，不影響案件狀態。
5. **維修人員處理**：按「開始處理」進入處理中狀態，處理完填寫維修紀錄（故障原因、
   處置方式、使用備品說明、處理起訖時間、維修前後照片/影片）。
6. **驗收**：報修人查看維修結果——
   - 驗收通過 → 結案，流程結束。
   - 驗收不通過 → 填寫原因退回「處理中」，維修人員重新處理，舊的維修紀錄保留、
     新增一筆新的紀錄，形成完整處理歷史。

## 案件狀態流程圖

```
新報修 → 已派工 → 處理中 → 待驗收 → 已結案
                              └──（驗收不通過）──> 處理中
```

所有轉換規則集中在 `App\Services\RepairRequestWorkflow`，共 25 種「目前狀態 x 目標
狀態」組合都有自動化測試驗證（`tests/Unit/RepairRequestWorkflowTest.php`），不合法
的操作會被擋下並顯示友善錯誤訊息，不會讓資料變成不一致的狀態。

## 角色（目前尚未接上真正的登入權限系統，見待確認事項）

| 角色 | 目前的操作方式 |
|---|---|
| 報修人（使用者） | 查知識庫、送出報修單、驗收通過/退回 |
| 主管 | 派工、重新指派 |
| 維修人員 | 開始處理、填寫維修紀錄 |

因為林政寬的帳號/角色權限系統尚未合併進本分支，以上角色目前**沒有登入區分**，
任何人打開網站都能操作所有功能；等權限系統合併後，會依角色限制能看到的按鈕。

## 測試涵蓋範圍

48 個自動化測試（Feature + Unit），涵蓋：
- 知識庫 CRUD 與驗證
- 報修單建立、附件驗證（含影片格式、檔案類型白名單）
- 完整狀態機（25 種狀態組合窮舉、派工、開始處理、驗收通過/退回、重新指派）
- 看板篩選（狀態/教室/維修人員）與未結案案件數統計
- 保養 NG 轉報修接口
- 4 個已知修過的迴歸 bug（工時計算方向、重複送出資料損毀、狀態不合法卻仍寫入）

## Demo 腳本（5-10 分鐘展示流程）

1. 開啟「自助知識庫」，示範查詢一篇文章、點「無法排除，前往報修」（自動帶入資料）。
2. 開啟「維修案件看板」，展示 7 種不同狀態的案例（一般故障、核心設備故障、需換
   備品、保養 NG 轉報修、已派工待處理、待驗收、已結案）與篩選功能。
3. 挑一張「新報修」案件，示範派工 → 開始處理 → 填維修紀錄（含備品/影片）→
   驗收退回 → 重新處理 → 驗收通過結案的完整流程。
4. 展示手機版排版（漢堡選單、表格捲動、篩選欄位自動換行）。

以上腳本使用的資料全部來自 `database/seeders/RepairRequestSeeder.php`，
執行 `php artisan migrate:fresh --seed` 即可重複產生，不需要現場臨時輸入資料。
