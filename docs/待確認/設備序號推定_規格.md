# 設備序號推定（規格草案，待與老師討論）

> 狀態：**只有規格，尚未實作**。提出：彭仕衡　整理日期：2026-11-11
> 相關文件：[設備與零件編號規則_彭仕衡.md](設備與零件編號規則_彭仕衡.md)（設備編號與零件編號怎麼取，序號推定要和它一致）

## 1. 要解決的問題

學校進貨設備通常是**大批量**（同品牌、同型號一次買幾十台），原廠序號高機率是**連續的流水號**（例如 `SN-DELL-0001`、`SN-DELL-0002`…）。
現在新增設備要一台一台手動輸入或掃描序號，批量建檔很花時間，也容易漏號、打錯。

目標：新增設備時，系統依「同一批的上一台」**推定下一個序號**，使用者確認即可，不必逐台輸入。

## 2. 範圍

| 項目 | 內容 |
|---|---|
| 做 | 新增設備時，序號欄提供「推定序號」；連續新增模式；（選配）批次新增 N 台 |
| 不做 | 不自動修改既有設備的序號；不預測沒有規律的序號；不處理有檢查碼或日期編碼的序號（見 4.3） |
| 不改資料表 | 推定是畫面與服務層的功能，**不新增欄位**。批次新增沿用 `devices` 現有欄位 |

## 3. 使用情境

1. **單台新增＋推定**：新增設備，選好類別、品牌、型號後，序號欄旁出現建議值「`SN-DELL-0007`（依 `SN-DELL-0006` 加 1）」，按一下採用，或直接改。
2. **連續新增**：儲存後留在新增頁，欄位保留類別、品牌、型號、教室，序號自動帶入下一個建議值；使用者可用相機掃設備上的條碼蓋掉建議值（見 5）。
3. **批次新增**（選配，建議第二階段）：輸入「起始序號」「數量」「教室」，一次建立 N 台；先預覽清單（設備編號、序號）再確認。

## 4. 推定規則

### 4.1 推定來源（依序找，找到就停）

1. 同「品牌＋型號」下，**最近建立**且序號有尾端數字的那一台。
2. 沒有的話，同「設備類別」下最近建立的一台。
3. 都沒有，不推定（欄位維持空白，不亂猜）。

### 4.2 遞增方法

- 取序號**尾端連續的數字**當流水號，前面的文字當前綴：`SN-DELL-0006` → 前綴 `SN-DELL-`、數字 `0006`。
- 數字加 1，**保持原本位數**並補零：`0006` → `0007`；`0099` → `0100`；`9999` → `10000`（位數自然增加）。
- 前綴與尾端非數字的後綴（例如 `-A`）原樣保留：`PJ-123-A` 視為「尾端不是數字」，不推定（見 4.3）。
- 推定出來的序號若**已被其他設備使用**，往後找下一個未使用的號碼（例如 `0007` 已存在 → `0008`）。

### 4.3 不推定的情況（避免給錯誤建議）

| 情況 | 處理 |
|---|---|
| 序號沒有尾端數字（例如 `ABCDEF`） | 不推定 |
| 序號是 EAN／UPC 等有檢查碼的條碼 | 不推定（加 1 會讓檢查碼錯誤） |
| 序號含日期（例如 `20261111-01`） | 不推定（無法判斷哪一段是流水號）——**需老師確認廠商序號格式** |
| 同品牌型號最近兩台的序號差距不是 1 | 仍推定，但畫面提示「最近兩台序號不連號，請確認」 |

### 4.4 推定一律只是「建議」

使用者可以不採用、可以改。**以使用者最後送出的值為準**，系統不會背著使用者改序號。

## 5. 畫面與操作

- 序號欄旁加一個「推定」按鈕與一行淡色提示：`建議 SN-DELL-0007（依 SN-DELL-0006 加 1）`。
- 選好品牌、型號後自動計算並顯示建議；點「推定」才填入欄位。
- 序號欄原本就有「相機掃描」按鈕（掃條碼直接填入序號）。**掃描優先於推定**：掃到的值直接填入，並以它當下一台推定的基準。
- 連續新增模式：儲存成功後留在新增頁，保留類別、品牌、型號、教室，序號欄帶入新的建議值。
- 批次新增（選配）：預覽表格列出每台的「設備編號、序號」，有衝突的列標紅，不能確認。

## 6. 設計重點（給實作的人）

| 項目 | 規格 |
|---|---|
| 位置 | 新增服務 `App\Services\SerialNumberSuggester`，方法 `suggest(?int $categoryId, ?string $brand, ?string $model): ?array`，回傳 `['serial' => …, 'basis' => 基準序號, 'continuous' => 最近兩台是否連號]` |
| 查詢 | 新增 API `GET devices/serial-suggestion?category=…&brand=…&model=…`（需 `devices.manage`） |
| 序號是否唯一 | **目前 `serial_number` 不是唯一欄位。** 建議：同「品牌＋型號」內不可重複（待老師確認），推定時一律避開已存在的序號 |
| 設備編號 | 批次新增時設備編號怎麼配，**依「設備與零件編號規則」文件的結論**，這份規格不另訂 |
| 稽核 | 批次新增每台都寫操作紀錄；紀錄「由推定／批次建立」 |
| 權限 | 沿用 `devices.manage` |
| 併發 | 兩個人同時新增可能推定出同一個號碼：儲存時檢查序號重複（現有驗證會擋），失敗就提示重新推定 |

## 7. 驗收條件

1. 同品牌型號最近一台是 `SN-DELL-0006` → 建議 `SN-DELL-0007`。
2. `SN-DELL-0099` → `SN-DELL-0100`；`SN-9` → `SN-10`。
3. 建議的號碼已被使用 → 自動跳到下一個未使用的號碼。
4. 沒有尾端數字、有檢查碼的序號 → 不給建議。
5. 找不到同品牌型號時，退到同類別；都沒有時不給建議。
6. 使用者改掉建議值後送出，存的是使用者改的值。
7. 掃描條碼填入序號後，下一台的建議以這個值為基準。
8. 沒有 `devices.manage` 權限的人打 API → 403。

## 8. 要跟老師討論的問題

1. 學校實際進貨的設備，序號**真的是連號嗎？**能不能拿幾批真實的序號當樣本（不同品牌）？
2. 同一批設備，序號的**前綴相同、只有尾端數字不同**嗎？有沒有中間夾英文字、日期或檢查碼的？
3. 序號要不要設成**唯一**？（同品牌型號內唯一，或全校唯一）
4. 是否需要**批次新增**（一次建立 N 台）？一次大約幾台、上限多少？
5. 批次建立的設備，**設備編號**要不要順便連號？（和「設備與零件編號規則」一起決定）
6. 批次建好後，是否需要**一次列印 QR 貼紙**？
7. 沒有序號的舊設備，要不要補登的功能？

## 9. 建議實作順序（老師確認後）

1. 第一階段：單台新增的「推定」與「連續新增」，加上服務與測試。
2. 第二階段：批次新增與預覽，視老師回覆決定要不要做。
